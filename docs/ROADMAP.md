# MinxTok 路线与版本冻结说明

> 最后更新：2026-10-30（追加 v7.x AI 社交路线）
> 当前线上版本：**6.0.6（最新稳定版）**
> 状态：**冻结，暂不开发 v5.00 之后的规划性大功能；只修明确 bug**

---

## 一、当前决定

- 2026-10-27 起，**4.1.10 为稳定线补丁版本**，线上继续使用 https://minxtok.pages.dev 。
- 没有明确指令，不再主动加功能、重构或改配置。
- 只处理影响使用的明确 bug；修完按补丁版本记录，不顺手扩大范围。
- v5.00 的四个方向已经评估，但**暂时不做**；需要重启时从本文件继续。

## 二、v5.00 候选方向（暂缓）

### 1. SurveyKing 题库

**结论：唯一硬风险项，不能直接假定有公开题库 API。**

公开文档里，题库/刷题是 SurveyKing 的产品模块；第三方集成提供的是 OAuth2、Webhook、消息通知等。MCP 接入文档明确写着「复杂逻辑、题库抽题等暂不支持」。因此不存在可以直接调用的公开「随机抽题」REST API。

可选的三种做法：

1. **导入题库（推荐先做）**：从 SurveyKing 导出 Excel/CSV，MinxTok 后台导入 D1，保存题干、选项、答案、解析、知识点、难度。运行时不依赖 SurveyKing，最稳。
2. **适配层（实验）**：定义统一的 `QuestionSource` 接口，本地题库和 SurveyKing 各自实现；Worker 代理请求，Token 只放服务端，加缓存、限流和失败回退。
3. **直接抓内部接口（不推荐）**：依赖登录态和内部 URL，随版本失效，也可能违反使用条款。

启动前必须确认：

- 部署形态：SaaS 还是自建；
- 版本号；
- 是否有接口文档、Token；
- 能否提供一条真实请求与返回示例；
- 题库授权和数据归属是否允许导入/同步。

### 2. 全部 Apple emoji

**结论：可做，但要先定版权和范围。**

系统原生 emoji 在 iPhone 上是 Apple 样式，在 Android/Windows 上不是。要全部统一成 Apple 样式，只能自托管图片资源，用 `emoji-datasource-apple` 这类数据加雪碧图，按 grapheme 替换成图片。

实现要点：

- 统一渲染层，覆盖聊天、日记、场景应答；
- 跳过代码块、公式和输入框；
- 支持 ZWJ、肤色、旗帜；
- 缺图回退系统 emoji；
- 只在最终渲染时替换，流式阶段不逐字替换；
- 图片资源懒加载，控制首屏体积。

风险：

- Apple 图片有版权限制，公开上线建议改用 Noto Color Emoji 或 Twemoji；
- 数据集版本决定能覆盖到哪一版 Unicode，新表情不会自动出现；
- 全量资源体积明显大于当前按需存放的 38 张 PNG。

### 3. 主题色

**结论：低风险，适合先做。**

- 现有颜色已经走 `--accent`，增加 5～6 套预设即可；
- 每套预设同时定义 `--accent` 和 `--accent-ink`，保证深色/浅色对比；
- 设置页放色块，存 `localStorage`，启动前应用，避免闪色；
- 建议只染按钮、链接、选中态，不把背景整体染色。

### 4. 语音转文字

**结论：后端已有基础，前端还没接。**

- 后端存在 `/api/stt`，Cloudflare 的 `CF_AI_TOKEN` 已配置；
- 还需确认 `CF_ACCOUNT_ID`、接口鉴权和实际可用性；
- 前端在输入条加麦克风：录音、60 秒上限、上传、回填文字，可选自动发送；
- iOS Safari 要单独测 `audio/mp4`，Android 是 `webm/opus`；
- Whisper 按音频时长计费，建议免费用户每日限次或按学分扣，服务端限流，音频不落盘。

## 三、建议顺序（重启时）

1. **4.1**：主题色 + 语音输入（低风险，先上）。
2. **4.2**：Apple emoji 或 Noto emoji（先定版权口径）。
3. **5.0**：SurveyKing 题库（先跑通导入，再考虑实时接口）。

如果必须一次性上 5.00，也按「主题 → 语音 → emoji → 题库」的顺序开发，题库放最后，并用功能开关隔离。

## 四、重启前需要明轩确认

- SurveyKing 是 SaaS 还是自建，能否提供接口文档/Token/返回示例；
- Apple emoji 是自用还是公开上线，是否接受图片版权风险；
- 主题色只要强调色，还是连背景一起染；
- 语音输入放在哪些页面，是否自动发送，免费额度怎么定。

# v7.x 路线：往「正规 AI 社交 App」走

> 现状（6.1.9）：单机 AI 陪伴 + 学习工具。v7 的重点不是继续加渲染细节，而是把「一个人用」变成「有身份、有关系、有内容流动」的产品。
> 原则：先骨架（账号/关系/消息），再多模态，再社区，最后商业化。每一阶段都要能独立上线、独立回滚。

## 一、v7.0 账号与身份（地基，必须先做）

1. **资料卡体系**：昵称、头像（本地上传 + 裁剪）、个性签名、个人主页、加入时间与使用天数；主页可看自己的情绪周报与学习统计。
2. **多角色设定**：AI 名字、称呼、语气（温柔/毒舌/学风）、头像、音色可切换，配 3～5 套官方预设；角色设定存服务端，跨设备同步。
3. **登录与安全**：短信/邮箱/微信扫码三选一；登录设备列表 + 异地登录提醒；注销账号（真正删数据）；密码找回。
4. **青少年模式**：默认开启，限制时长、内容分级、禁止付费；家长可设「守护口令」查看使用时长。
5. **隐私合规**：隐私政策、用户协议、数据导出（JSON）、一键删除全部对话；PIPL 要求的最小必要采集清单。

## 二、v7.1 社交关系（第一次「有别人」）

1. **好友与关注**：搜索 ID/手机号加好友、扫二维码加好友、好友备注与分组。
2. **私信（1v1）**：文字、图片、语音条、引用回复、已读回执；AI 不参与人类私信（边界必须清楚）。
3. **群聊 + 群内 AI**：3～200 人；群内可 @AI 让它答题/总结/查化学式；AI 发言要标注「这是 AI」。
4. **分享卡片**：把一段对话、一张公式卡、一份情绪周报拼成竖版卡片，可存图、可分享到微信/朋友圈，带站点水印。
5. **通知中心**：站内红点 + Web Push（iOS 需引导添加到主屏）；消息免打扰、按类型分流。

## 三、v7.2 多模态 AI（能力跃迁）

1. **拍照解题**：相机/相册上传，OCR + 公式识别 → 直接出解题步骤；化学方程式配平单独优化。
2. **实时语音对话**：按住说话改成「连续对讲」，AI 边说边出字，可打断；音色走同一个角色设定。
3. **长期记忆中心**：把「记住的事」做成列表（谁、什么偏好、什么约定），可查看、可编辑、可删除；记忆向量检索，控制注入条数。
4. **工具调用**：联网搜索、计算器、单位换算、化学式求解、代码执行（沙箱）、天气/地图；调用过程在气泡里可见、可折叠。
5. **双模型路由**：快答走小模型、难题自动升大模型；「深度思考」开关，把思考过程折叠成一行「思考了 8 秒」。
6. **安全护栏**：内容分级（未成年/成人）、敏感话题拒答模板、防自伤提示与求助资源、防越狱（提示词注入检测）。

## 四、v7.3 内容生态（留得住人）

1. **动态广场**：发帖（文字/图片/公式卡）、点赞、评论、话题标签、关注流 + 推荐流（先做时间序，别急着上算法）。
2. **同好匹配**：按学科、年级、城市、兴趣标签推荐「可能聊得来的人」；给出推荐理由，不做陌生人随机搭讪。
3. **学习中心升级**：错题本自动归档、知识点图谱、周学习计划、连续打卡与成就徽章。
4. **共享题库/课程**：老师/学霸可发布题目集与课程卡，他人可收藏；带举报与审核队列。
5. **UGC 模板**：公式卡、笔记卡、周报卡、书摘卡，一键生成统一排版的图片。

## 五、v7.4 商业化与运营

1. **订阅制**：免费/Plus/Pro 三档，权益包括每日额度、模型档位、记忆容量、主题与音色、去水印；保留现有充值码体系做补充。
2. **成长体系**：等级、经验、连续使用、邀请奖励（拉新给双方额度），防刷（设备指纹 + 频控）。
3. **运营后台**：用户增长、留存、付费转化、额度消耗、AI 成本（按模型/接口）看板；封禁与申诉流程。
4. **推送与召回**：每日一问、情绪周报、学习提醒；频控到「不打扰」的程度。
5. **内容审核**：敏感词 + 模型双筛，举报入口，违规分级处置（提醒/限流/封禁）。

## 六、v7.5 基础设施

1. **消息实时化**：Durable Objects 或 WebSocket，替代轮询；在线状态、正在输入。
2. **PWA**：可安装、离线草稿、后台同步；App 图标与启动图。
3. **可观测性**：前端错误上报（Sentry 或自建）、接口耗时与 AI 首字延迟指标、灰度发布与开关。
4. **数据与备份**：D1 定期导出、KV 键命名规范、缓存分层（本地 → KV → D1）。
5. **性能预算**：首屏 < 1.5s、流式首字 < 800ms、长列表虚拟滚动。

## 七、建议节奏

| 阶段 | 版本 | 主题 | 预计工时 |
| --- | --- | --- | --- |
| 第一步 | 7.0.x | 资料卡 + 多角色 + 青少年模式 + 隐私合规 | 3～4 周 |
| 第二步 | 7.1.x | 好友 + 私信 + 通知中心 + 分享卡片 | 4～6 周 |
| 第三步 | 7.2.x | 拍照解题 + 实时语音 + 记忆中心 | 4～6 周 |
| 第四步 | 7.3.x | 广场 + 同好匹配 + 学习中心升级 | 6～8 周 |
| 第五步 | 7.4.x | 订阅 + 运营后台 + 审核 | 持续 |

## 八、必须先定的三件事

1. **真人社交要不要做**：一旦有私信和广场，就必须有人工/自动审核与举报通道，成本会上去；只做「AI + 内容广场」会轻很多。
2. **未成年合规口径**：默认青少年模式、付费限制、内容分级，需要明确到什么程度。
3. **成本模型**：语音与图片识别按次计费，必须先定免费额度，否则用户一涨就亏。
